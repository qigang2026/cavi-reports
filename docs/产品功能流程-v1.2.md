## ⚠️ v1.2.1 关键修正

> **PM 反馈纠正**：v1.2 中 S1 业务场景被描述为"用户主动触发报告生成"，但实际流程是：
>
> **用户 → 跳转 WhatsApp（带报告参数） → 销售收对话 → 销售在 Cavi 销售工作台一键复制参数 → 销售在 Cavi 后台点击"立即生成" → 触发原 PRD v1.1 的 5 步报告生成流程 → 系统自动通过 WhatsApp 回传报告给用户**
>
> **关键认知**：
> - **销售是"AI 报告生成的触发代理"**，不是系统直接调用
> - **触发方标记**：从 `trigger=user_request` 改为 `trigger=user_request_via_sales`（v1.2.1 新增子类型）
> - **S1 业务场景被拆为 4 个子步骤**：S1.1 跳转 WA / S1.2 收对话+复制参数 / S1.3 销售触发后台 / S1.4 报告回传
> - **新增角色维度**：销售兼任"报告生成的触发者" + "线索承接者"（双角色）
> - **新增接口**：WA Business API（自动发报告 PDF）+ Cavi 销售工作台（参数解析+复制）

**v1.2.1 影响范围**：
| 章节 | 变化 |
|------|------|
| 一 业务全景 | 阶段 2 拆为 4 子步：跳转 WA → 收对话+参数 → 触发后台 → 报告回传 |
| 二 业务场景 | S1 拆为 S1.1/S1.2/S1.3/S1.4 四子场景 |
| 三 角色与职责 | 销售新增"触发代理"角色 |
| 四 端到端流程图 | 阶段 2 重新画图 |
| 五 时序图 | 新增"销售工作台"泳道 |
| 六 关键节点 | 节点 ① 触发重新拆解 |

## 〇、本版本与 v1.1 的差异

> **本版本不替代 PRD v1.1，而是 v1.1 的"业务范围扩展"**。报告生成主流程（节点 ① 触发 → ② 接入 → ③ 数据 → ④ 生成 → ⑤ 落地）保持不变，新增 3 类业务场景与 3 个新节点。

| 变化 | v1.1 | v1.2 |
|------|------|------|
| 业务场景数 | 4（S1-S4） | **6**（新增 S0 长期心智触达 / S5 试驾预约 / S6 优惠留资）|
| 端到端流程范围 | 车系页 → 报告落地 | **车系页（外圈触达）→ 报告生成 → 报告呈现 → 留资/试驾 → 销售跟进** |
| 节点数 | 5 步 | **8 步**（新增 ⑥ 试驾 ⑦ 留资 ⑧ 跟进）|
| 角色数 | 5 类 | **8 类**（新增销售、运营、销售主管）|
| 错误码 | E001-E500 | E001-E801（新增 6/7/8 段错误码）|
| 关键指标 | 7 个 | **14 个**（新增留资/试驾/跟进 3 类共 7 个）|

## 二、业务场景（v1.2.1 = 9 种触发）

> **v1.2.1 关键变化**：S1 业务场景被拆为 4 个子步骤（S1.1 / S1.2 / S1.3 / S1.4），明确"销售协作"是核心环节。

| # | 场景 | 触发方 | 阶段 | 频率 | 优先级 | 关联模块 |
|---|------|--------|------|------|--------|---------|
| **S0** | **长期"省"心智触达**（v1.2 新）| 首页 banner / 榜单·降价榜 / 条件找车·省钱专区 / 车系页返现入口 | 0→4C | 持续 | high | 长期留资前置（无报告）|
| **S1.1** | **用户跳转 WhatsApp**（v1.2.1 新）| 车系页点"获取完整报告" | 1→2 | 实时 | high | WA Business API |
| **S1.2** | **销售收对话+解析参数**（v1.2.1 新）| 销售工作台自动解析 WA 消息 | 2 | 实时 | high | Cavi Sales Workbench |
| **S1.3** | **销售触发后台报告生成**（v1.2.1 新）| 销售在 Cavi 后台点"立即生成" | 2 | 实时 | high | AI 报告生成（v1.1）|
| **S1.4** | **报告自动回传 WhatsApp**（v1.2.1 新）| 系统回调 → WA Business API 发 PDF | 2 | 实时 | high | WA Business API |
| **S2** | 数据变更触发 | 4 数据源任一字段更新 | 2 | 实时 | high | AI 报告生成（v1.1）|
| **S3** | 定时刷新 | 后台 cron 02:00 | 2 | 每日 1 次 | normal | AI 报告生成（v1.1）|
| **S4** | 人工强制（PM/运营）| 后台手动（也走 Cavi 后台）| 2 | 按需 | normal | AI 报告生成（v1.1）|
| **S5** | **预约试驾**（v1.2 新）| 报告段 08 第 2 张 next-card / 外部入口 | 4B | 实时 | high | 试驾流程 |
| **S6** | **优惠留资**（v1.2 新）| 报告/榜单/车系返现 → 领券页 | 4C | 实时 | high | 留资页（长期"省"心智）|

**S1 子场景的串联关系**（v1.2.1 关键）：
```
S1.1 用户跳转 WA    →    S1.2 销售收对话+解析    →    S1.3 销售触发后台    →    S1.4 报告回传
 (wa.me/?text=)          (Cavi Sales 解析)         (Cavi 后台点击)          (WA 自动发 PDF+H5)
```

**S0 的特殊性**：S0 不进报告生成流程——用户只是来领券/看降价，触发后直接走长期留资链路。这是"无报告线索"。

**S1 与 S2-S4 的关系**：S1 是经"销售协作"的触发路径，S2-S4 是"系统自动"路径。两者走同一个 Cavi 后台接口（节点 ②-⑤），仅触发方不同（销售手动 vs 系统自动）。

## 三、角色与职责

| 角色 | 职责 | 触发场景 | v1.2 状态 |
|------|------|---------|---------|
| **用户**（车系页访客 / 报告读者）| 浏览 → 点 CTA → 留资 | S0/S1/S5/S6 | 原有 |
| **首页/榜单访客** | 浏览 → 领券/看降价 | S0 | **v1.2 新** |
| **后台调度系统** | 定时刷新 / 数据变更检测 | S2/S3 | 原有 |
| **PM / 运营** | 后台手动触发 / 配置券 / 配置降价榜 | S4 + 阶段 0 配置 | 原有 + **v1.2 扩配置范围** |
| **后端接入层** | 接收请求、拉数据、缓存、调用 AI、落报告 | 所有 | 原有 + **新增留资/试驾 API** |
| **AI Agent**（cavi-guide-gen）| 填字段、LLM 润色、5 步校验、生成 MD | S1-S4 | 原有 |
| **数据源**（4 个系统）| CAVI API / 评分 / 销售 / 金融 | S1-S4 | 原有 |
| **人工审核** | 5% 抽样审核报告 | S1-S4 | 原有 |
| **销售顾问**（v1.2 新）| 接 WhatsApp / 跟进留资 / 协助试驾 / 落实优惠方案 | S5/S6 + 阶段 5 | **v1.2 新** |
| **销售主管**（v1.2 新）| 线索分配 / 跟进率监控 / 转化分析 | 阶段 5 | **v1.2 新** |
| **前端**（不在本系统）| 报告 H5 渲染、留资页 UI、试驾页 UI | 全部 UI | 原有 + **新增 2 个页面** |

**关键原则（沿用 + 强化）**：
- **AI 端不直接面向用户**——所有触发经后端
- **AI 端不修改数字**——v1.1 硬约束不变
- **线索统一进 CRM**（v1.2 新）——无论从哪条路径来的留资，都汇总到同一线索库

### 7.1 v1.1 错误码（沿用）

| 节点 | 错误码 | 处理 |
|------|--------|------|

| 数据 | E103 | 提示陈旧，PM 决定 |
| 生成 | E201/E202 | 不重试 |
| 生成 | **E203** | AI 改数字 = P0，报警，重生成 |
| 生成 | E301/E302 | 重试 1 次（30s）|
| 落地 | E401/E500 | 重试 1 次（60s）|

### 7.2 v1.2.1 新增错误码（含销售协作 S1.1-S1.4）

| 节点 | 错误码 | 说明 | 处理 |
|------|--------|------|------|
| **S1.1 跳转 WA** | **E001_WA_JUMP_FAILED** | wa.me 链接拼装失败或跳转被拦截 | 回退：保留车系页 + 提示"复制下方链接到 WhatsApp" |
| **S1.1 跳转 WA** | **E002_WA_NOT_INSTALLED** | 用户没装 WhatsApp | 引导下载 WhatsApp / 改用销售电话兜底 |
| **S1.2 销售收对话** | **E010_WEBHOOK_TIMEOUT** | WA 消息未在 30s 内到达销售工作台 | 销售手动刷新 + 报警 |
| **S1.2 销售收对话** | **E011_PARSE_FAILED** | 销售工作台无法解析消息中的报告参数 | 提示销售"手动填写 series_id" + 留 entry |
| **S1.2 销售收对话** | **E012_LEAD_DUPLICATE** | 同一 lead_id 30s 内重复触发 | 去重 + 提示"已处理，请勿重复点击" |
| **S1.3 销售触发后台** | **E020_COPY_FAILED** | 一键复制参数到剪贴板失败 | 提示销售"长按复制" |
| **S1.3 销售触发后台** | **E021_TRIGGER_TIMEOUT** | 销售未在 5min 内触发（超过 SLA）| 升级到销售主管 + 客户 WA 消息提示"顾问正在准备" |
| **S1.4 报告回传** | **E030_WA_API_FAILED** | WA Business API 发送失败 | 重试 1 次 + 转 PDF 邮件兜底 |
| **S1.4 报告回传** | **E031_PDF_GENERATION_FAILED** | MD 转 PDF 失败 | 发 H5 链接（无 PDF）+ 报警 |
| 阶段 3 呈现 | **E501** | 报告 H5 加载失败 | 回退到上一版 MD + 显示"重新加载"按钮 |
| 阶段 3 呈现 | **E502** | 段 08 next-card URL 失效 | 走 WhatsApp 兜底入口 |
| 节点 ⑥ 短期留资 | **E601** | 留资提交失败（CRM 写不进）| 本地缓存 + 60s 重试 + 报警 |
| 节点 ⑥ 短期留资 | **E602** | 留资字段非法（手机号格式）| 前端校验，不发请求 |
| 节点 ⑥ 短期留资 | **E603** | 销售超时未响应（>5min）| 升级到销售主管 |
| 节点 ⑦ 试驾 | **E701** | 经销商列表为空 | 兜底显示"联系销售" + 隐藏时段选择 |
| 节点 ⑦ 试驾 | **E702** | 时段被占（双订）| 实时刷新 + 提示"该时段刚被预订" |
| 节点 ⑦ 试驾 | **E703** | 试驾提交失败 | 同 E601 |
| 节点 ⑥' 长期留资 | **E801** | 领券失败（券库存不足）| 显示"已领完"+ 引导留资订阅到货通知 |
| 节点 ⑥' 长期留资 | **E802** | 优惠方案配置缺失 | PM 报警 + 隐藏 CTA |
| 节点 ⑧ 跟进 | **E901** | CRM 分配失败 | 兜底主管手动分配 |
