**文档版本**：v1.2
**创建日期**：2026-08-27
**修订日期**：2026-08-27（v1.2：明确 1 个标杆车型 + AI 润色不编数 + 4 个真实数据源）
**目的**：让团队对"AI 怎么把车型数据变成 MD 报告"这件事建立共同认知
**范围**：只覆盖 **MD 文档的生成**；HTML 渲染、埋点、前端样式**不在本文档范围**

---

## 一、我们解决什么问题

用户来到 AUTOCAVA 看车时，面对的是上百款车型、上千个参数、上百种金融方案。**没人能读懂**这些数字背后的含义。

我们要做的：用 AI 把"系统原始数据"组织成一份**讲人话、可决策**的 MD 文档，由前端用同一个 HTML 模板渲染成报告。

**对用户的承诺**：30 秒内回答 3 个问题 ——
- 值不值得买？（CAVI 评分 + 一句洞察）
- 要花多少钱、怎么买？（价格 4 卡 + cta-bar）
- 跟同价位对手比怎么样？（3 张并排卡）

## 四、AI 工作模式（核心原则）

> **PM 已确认：系统给原始数据，AI 负责润色 + 翻译。AI 不得编造数字或事实。**

| 类型 | 谁负责 | 例子 |
|------|--------|------|
| **系统字段**（结构化）| 后端系统 | 价格、版本、CAVI 分、销量、评论原文 |
| **AI 润色**（自然语言）| AI | 副标题、洞察、推荐语（≤ 30 字）|
| **AI 翻译**（多语言时）| AI | 把系统给的英文版翻译成西语 |

**AI 不可触碰**（硬约束）：
- ❌ 不许编造价格、销量、评分、评论
- ❌ 不许把"3.9"改成"4.0"让数据好看
- ❌ 不许"润色"时篡改原始数据含义
- ✅ 可以润色：把"118 HP 5.3L/100km"变成"动力够用且省油"
- ✅ 可以翻译：把英文 raw 数据译成西语
- ✅ 可以拼装：把系统分 + 评论拼成"一句洞察"

**校验机制**：质量保证手册有专门的"AI 字段合规校验"。

## 五、端到端流程

```
┌─────────────────┐
│ ① 输入参数       │  series_id=356（标杆固定）
└────────┬────────┘
         ↓
┌─────────────────┐
│ ② 数据获取        │  CAVI API · CAVI 评分 · 销售 · 金融 API
└────────┬────────┘  失败重试 / 缓存 / 兜底
         ↓
┌─────────────────┐
│ ③ AI 生成 MD     │  读 standard-template-v3 + 字段表
└────────┬────────┘  系统字段直接填，AI 只润色+翻译
         ↓
┌─────────────────┐
│ ④ 质量校验        │  必填 / 8 段 / 跨字段 15 条 / eyebrow 字面
└────────┬────────┘
         ↓
┌─────────────────┐
│ ⑤ 输出 MD        │  reports/es/nissan-versa-2026.md
└────────┴────────┘  写文件 + 数据快照
```

**关键约束**：

| 约束 | 说明 |
|------|------|
| **数据可靠** | 字段值必须有源（系统），AI 不许编 |
| **风格一致** | 所有报告的 8 段结构 + 西语 block-eyebrow 字面必须一致 |
| **可回放** | 同一 series_id + 同一数据快照 → 同一 MD 哈希 |
| **可校验** | 输出可被自动 + 人工两重校验 |

| 04 | `04 · CAVI · RESEÑAS` |
| 05 | `05 · COST` |
| 06 | `06 · PROTECTION` |
| 07 | `07 · COMPETITORS` |
| 08 | `08 · SIGUIENTE PASO` |

## 七、与其他系统的边界

```
                  ┌──────────────┐
                  │ MD 生成系统    │ ← 本文档范围
                  │ (我们的责任)  │
                  └──────┬───────┘
                         │ 输出 MD 文件
                         ↓
              ┌────────────────────┐
              │ reports/es/...md    │ ← 文件落地
              └────────┬───────────┘
                       │ 静态托管
                       ↓
              ┌────────────────────┐
              │ 前端 HTML 渲染       │ ← 不归我们
              │  templates/pc-v1   │
              └────────┬───────────┘
                       │ 渲染页
                       ↓
                  用户看到
```

**我们不做的**：
- HTML 模板的样式（CSS / 响应式）
- 前端交互（Tab / Calculator / 分享）
- 埋点 / 转化追踪
- 数据获取 API 的具体实现（后端做）
- 多车型 / 多市场 / 多语言扩展

**我们做的**：
- MD 文档的"内容"完整且可靠
- MD 文档能 1:1 渲染出 pc-v1.html
- 字段值有源（系统给）、AI 润色（不编数）
- 跨字段一致、西语 eyebrow 字面、8 段结构

## 十、风险与缓解

| 风险 | 缓解 |
|------|------|
| AI 润色时篡改数字 | 硬约束 + 校验：润色后必须保留原始数字，"118 HP"不许变 |
| 数据源失败 | 后端字段级缓存 + 兜底默认值 + 告警 |
| 西语翻译质量 | AI 基于系统原文翻译，不许自由发挥 |
| 模板字段遗漏 | 8 段结构 + 必填字段双重校验 |
| 价格变动导致过时 | 数据快照记录 fetched_at，2× TTL 触发警告 |
