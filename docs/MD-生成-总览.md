# MD 生成总览

**文档版本**：v1.0
**创建日期**：2026-08-27
**目的**：让团队对"AI 怎么把车型数据变成 MD 报告"这件事建立共同认知
**范围**：只覆盖 **MD 文档的生成**；HTML 渲染、埋点、前端样式**不在本文档范围**

---

## 一、我们解决的问题

用户来到 AUTOCAVA 看车时，面对的是上百款车型、上千个参数、上百种金融方案。**没人能读懂**这些数字背后的含义。

我们要做的：用 AI 把"系统数据 + 销售数据 + 评论数据"组织成一份**讲人话、可决策**的 MD 文档，由前端渲染成 H5/PC 报告页。

**对用户的承诺**：30 秒内回答 3 个问题 ——
- 值不值得买？（CAVI 评分 + 一句结论）
- 要花多少钱、怎么买？（价格 4 卡 + cta-bar）
- 跟同价位对手比怎么样？（3 张并排卡）

## 二、端到端流程

```
┌─────────────────┐
│ ① 输入参数       │  series_id / market / lang / template_id / force_update
└────────┬────────┘
         ↓
┌─────────────────┐
│ ② 数据获取        │  CAVI API · 销售系统 · 银行/厂家数据 · 评论库
└────────┬────────┘  失败重试 / 缓存 / 兜底默认值
         ↓
┌─────────────────┐
│ ③ AI 生成 MD     │  读 standard-template-v3 + 字段表 + 风格规范
└────────┬────────┘  填 8 段结构 + frontmatter
         ↓
┌─────────────────┐
│ ④ 质量校验        │  必填字段 / 必含章节 / 变量替换 / 跨字段一致性
└────────┬────────┘
         ↓
┌─────────────────┐
│ ⑤ 输出 MD        │  reports/{lang}/{model}-{year}.md
└────────┴────────┘  写文件 + 返回数据快照版本号
```

**关键约束**：

| 约束 | 说明 |
|------|------|
| **数据可靠** | 字段值必须有源（API/库/AI），不能凭空 |
| **风格一致** | 所有报告的 8 段结构 + 西语 block-eyebrow 字面必须一致 |
| **可回放** | 同一 series_id + 数据快照，生成的 MD 哈希必须一致 |
| **可校验** | 输出可被自动 + 人工两重校验 |

## 三、关键设计决策

### 3.1 8 段结构（与前端模板对齐）

```
段 0：首屏（Hero + Spec strip + Trim selector + Compare bar）
段 02：价格与金融方案
段 03：核心卖点
段 04：CAVI 口碑评价
段 05：用车成本
段 06：购车保障
段 07：主要竞品
段 08：行动入口
```

> 详见 `docs/MD-数据-需求清单.md` 每段的字段定义。

### 3.2 西语 block-eyebrow 字面锁定

每个内容段的 eyebrow 是前端模板的"标识符"，**字面不能变**：

| 段 | block-eyebrow |
|----|---------------|
| 02 | `02 · PRECIO Y FINANCIAMIENTO` |
| 03 | `03 · CORE SELLING POINTS` |
| 04 | `04 · CAVI · RESEÑAS` |
| 05 | `05 · COST` |
| 06 | `06 · PROTECTION` |
| 07 | `07 · COMPETITORS` |
| 08 | `08 · SIGUIENTE PASO` |

> 当前定位为**西语字面**——和西语模板强绑定。多语言扩展时再讨论是否需要翻译版本。

### 3.3 CAVI 4 维度是配置化（不是硬编码）

pc-v1（西语 MX 燃油车 Versa）4 维度：
- cajuela（后备厢） / consumo（油耗） / seguridad（安全） / ruido（噪音）

cn-demo（中文 电动车 SUV）4 维度：
- 外观 / 内饰 / 智驾 / 售后

→ **不同模板族**有自己的 4 维度定义。`cavi_dimensions` 在 v3 模板里是 4 个键值对（label + value），但**维度标签由模板族决定**，不是固定的。

### 3.4 数据来源 = 系统数据 + AI 文案

| 类型 | 例子 | 谁来写 |
|------|------|--------|
| **系统数据**（结构化）| CAVI 评分、价格、版本、销量、评论 | 不需 AI，直接读 API/库 |
| **AI 文案**（自然语言）| 副标题、洞察、推荐语、翻译 | AI 生成，受风格规范约束 |
| **混合** | CAVI 一句洞察 | 系统给评分 + AI 写话（≤ 30 字）|

**规则**：能系统给的就不让 AI 编；必须 AI 写的必须有"风格规范"约束。

### 3.5 模板族配置（Template Family）

每份 MD 报告绑定一个 template_id，模板族决定：
- 西语 eyebrow 是否字面渲染
- CAVI 4 维度标签
- 金融产品的卡类型
- 章节中文/西语标题

当前已识别 2 个模板族：
- `pc-mx-fuel-sedan`（西语 MX 燃油车，对应 pc-v1.html）
- `pc-cn-ev-suv`（中文电动车 SUV，对应 cn-demo.html）

未来扩展：`pc-cn-fuel-sedan` / `pc-co-xxx` / `pc-ar-xxx` ...

## 四、与其他系统的边界

```
                  ┌──────────────┐
                  │ MD 生成系统    │ ← 本文档范围
                  │ (我们的责任)  │
                  └──────┬───────┘
                         │ 输出 MD 文件
                         ↓
              ┌────────────────────┐
              │ reports/{lang}/...md │ ← 文件落地
              └────────┬───────────┘
                       │ 静态托管
                       ↓
              ┌────────────────────┐
              │ 前端 HTML 渲染       │ ← 不归我们
              │  H5 / PC / Modal   │
              └────────┬───────────┘
                       │ 渲染页
                       ↓
                  用户看到
```

**我们不做的**：
- HTML 模板的样式（CSS / 响应式 / Modal）
- 前端交互（Tab 切换 / Calculator / 分享）
- 埋点 / 转化追踪
- 业务策略（哪些车展示、给谁展示、限时优惠弹窗）

**我们做的**：
- MD 文档的"内容"完整且可靠
- MD 文档能 1:1 渲染出前端模板
- 字段值有源、可追溯、可校验

## 六、成功标准

| 维度 | 目标 |
|------|------|
| **覆盖率** | 10+ 车型 MD 文档，格式一致率 > 95% |
| **可靠性** | 字段缺失率 < 1%，跨字段不一致 < 0.5% |
| **效率** | 单车型生成 < 60s（含 AI 调用）|
| **可回放** | 同一输入 + 同一数据快照 → 同一 MD 哈希 |
| **可扩展** | 新增一个模板族，配置 ≤ 1 个工作日 |

---

## 七、风险与缓解

| 风险 | 缓解 |
|------|------|
| AI 写的话与系统数据冲突 | 混合字段用"系统评分 + AI 润色"，AI 只改不改数 |
| 模板族扩展失控 | 模板族配置统一在 `template_families.yaml`，新增必须经 PM 评审 |
| 数据源 API 不稳定 | 字段级缓存 + 兜底默认值 + 失败告警 |
| 西语翻译质量参差 | AI 必须基于系统给的字段翻译，不许自由发挥 |
| 老 HTML 报告没 MD 源 | 历史报告允许纯 HTML 兜底，新报告必须有 MD 源 |
