## 一、需求概述

### 1.1 背景

AUTOCAVA 目前用户在车系页面的线索提交转化较低，通过购车报告作为钩子来引导用户提交线索获取报告，从而达到车系页用户线索提交转化的目标。
购车报告以 H5 形式呈现给用户，确保后续：
1. 购车报告的内容更新及时
2. 报告的浏览记录可查询
3. 报告中植入的 cavi 能承接通过分享进入报告页面的用户咨询

### 1.2 目标

| 目标 | 描述 | 验收标准 |
|---|---|---|
| 文档标准化 | 制定 MD 文档规范 | AI 生成 10+ 车型 MD 文档，格式一致率 > 95% |
| model 体系建立 | 车型维度唯一标识 | 每个车型有唯一 model，支持埋点追溯 |
| Skill 规范化 | 定义 AI 生成流程 | cavi-guide-gen Skill 生成文档成功率 > 99% |
| **数据可靠**（v1.1 强化）| **AI 不许篡改系统数字** | **AI 字段合规率 = 100%** |

### 1.3 范围

**本期范围**：
- 制定 MD 文档规范
- 更新 cavi-guide-gen Skill
- 覆盖 cava 平台所有车型
- 明确购车报告 H5 页面样式
- 明确基础埋点内容
- **明确 AI 业务流程**（v1.1 强化）

**范围外**：
- HTML 模板的样式设计（CSS / 响应式）—— 由前端团队负责
- 前端交互（Tab 切换 / Calculator / 分享）—— 由前端团队负责
- 多车型 / 多市场 / 多语言扩展—— 当前只支持 Versa 1 个标杆车系

## 二、业务流程（v1.1 新增）

> 本章回答"AI 怎么把车型数据变成 MD 报告"。

### 2.1 业务场景（4 种触发）

AI 生成 MD 报告的触发场景：

| # | 场景 | 触发方 | 频率 | 优先级 |
|---|------|--------|------|--------|
| **S1** | **用户主动请求** | 用户在车系页点击"获取购车报告" | 实时（每用户每次访问 1 次）| high |
| **S2** | **数据变更触发** | 4 个数据源任一字段更新（如价格、CAVI 分、评论）| 实时 | high |
| **S3** | **定时刷新** | 后台 cron 每天凌晨 2:00 跑全量 | 每日 1 次 | normal |
| **S4** | **人工强制** | PM / 运营在后台手动触发 | 按需 | normal |

**当前实现**：4 种场景都通过同一个 SKILL 调用入口进入（`series_id` + 必填参数），由后端调度系统决定触发时机。

### 2.2 角色与职责

| 角色 | 职责 | 触发场景 |
|------|------|---------|
| **用户**（车系页访客）| 点击"获取报告"按钮 → 提交线索 | S1 |
| **后台调度系统** | 定时刷新 / 数据变更检测 | S2, S3 |
| **PM / 运营** | 后台手动触发 | S4 |
| **后端接入层** | 接收调用方请求、拉取 4 个数据源、缓存管理、调用 AI Agent | 所有 |
| **AI Agent**（cavi-guide-gen）| 按字段表填数据、调用 LLM 润色、生成 MD 文档、5 步校验 | 所有 |
| **数据源**（4 个系统）| CAVI API / CAVI 评分系统 / 销售系统 / 金融 API | 所有（被调用方）|
| **人工审核** | 5% 抽样审核 | 所有（兜底）|
| **前端**（不在本系统）| 读取 MD 文件，渲染 H5/PC 报告 | — |

**关键原则**：
- **AI 端不直接调数据源**—— 后端负责数据拉取和缓存
- **AI 端不直接面向用户**—— 调用方统一是后端
- **AI 端不修改数字**—— 系统给的数字原样填入

### 2.3 端到端流程图

```
┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 触发场景 │ →  │ 后端接入  │ →  │ 4 数据源  │ →  │ AI Agent │ →  │ MD 文件   │
│ S1-S4   │    │ 接收请求  │    │ 拉取数据  │    │ 生成+校验 │    │ 落地      │
└─────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
   ①              ②              ③              ④             ⑤
  用户/         series_id      缓存+重试     标准模板+       reports/es/
  调度/         参数校验       兜底默认值     字段表+LLM     nissan-versa-
  人工                          (E101-E103)     5步校验         2026.md
                                                             +数据快照
```

**5 步详解**：

| 步骤 | 谁 | 做什么 | 输入 | 输出 | 错误处理 |
|------|---|--------|------|------|---------|
| **① 触发** | 用户/调度/人工 | 发起报告生成请求 | — | `series_id` + 必填参数 | E001/E002 |
| **② 接入** | 后端 | 校验参数、查缓存、看是否需要拉数据 | 参数 | 数据快照请求 | E001 |
| **③ 数据** | 4 数据源 | 拉取车系/版本/CAVI/销售/金融 | series_id | 完整字段表 | E101/E102/E103 |
| **④ 生成** | AI Agent | 按字段表填系统字段 → LLM 润色 AI 字段 → 8 段结构组装 → 5 步校验 | 完整字段表 | MD 文档 | E201/E202/E203/E301/E302 |
| **⑤ 落地** | 后端 | 写文件 + 保存数据快照 + 触发部署 | MD 文本 | 报告上线 | E401/E500 |

**关键交互原则**：
- 后端**并行**拉 4 个数据源（不串行）
- AI Agent **只**跟后端交互，**不直接**调数据源
- LLM 润色只针对 AI 字段，系统字段原样填入
- 校验在 MD 落地前完成，不合格不写入

### 2.5 关键节点说明

#### 节点 ②（接入）参数校验

```yaml
必填: { series_id: int }
可选: { force_update: bool, priority: enum, callback_url: url, metadata: object }
校验:
  - series_id 在白名单（当前仅 356）
  - force_update=true 强制无视缓存
  - priority=high 跳过排队
```

#### 节点 ③（数据）4 个数据源

| 数据源 | 提供字段 | 失败行为 |
|--------|---------|---------|
| CAVI 内部 API | 车系 / 6 版本 / 规格 / MSRP / official / 月供估算 | E102 阻塞（关键字段）|
| CAVI 评分系统 | 综合分 4.6 / 推荐率 89% / 4 维度评分 | E102 阻塞 |
| 销售系统 | 月销量 7,486 / 排名 / 评论人数 | 兜底 null |
| 金融 API | BBVA 36 / Nissan 厂家 48 / 交换补贴 | 部分缺失 → 整段跳过 |

**关键规则**：价格 / 版本 / CAVI 总分任一缺失 → **阻塞**，不生成。

#### 节点 ④（生成）AI Agent 内部流程

```
字段表（系统原始数据）
   ↓
① 系统字段原样填入（AI 不可改）
   ↓
② LLM 润色 AI 字段（混合 / AI 字段）
   - 副标题、洞察、推荐语
   - 竞品 pros/cons（不涉数字）
   - saving_tips
   ↓
③ 8 段结构组装
   - 首屏 + 02..08
   - 西语 eyebrow 字面锁定
   ↓
④ 5 步校验
   - 字段完整性
   - 跨字段一致性（15 条）
   - 结构完整性（8 段 + eyebrow 字面）
   - **AI 字段合规（不许改数字）**
   - 风格合规
   ↓
⑤ 输出 MD 文本
```

**关键规则**（v1.1 强化）：
- ❌ AI 不得编造价格/销量/评分/评论
- ❌ AI 不得把"3.9"改成"4.0"
- ✅ AI 可润色字面、翻译、拼装成洞察
- 违反 → E203 P0 错误

#### 节点 ⑤（落地）输出 + 快照

```yaml
# 落地产物
md_file: reports/es/nissan-versa-2026.md
snapshot: reports/_snapshots/nissan-versa-2026.20260827-1430.yaml
log: logs/md-gen/2026-08-27/nissan-versa-2026.log

# 数据快照（用于回放）
data_version: v20260827-1430
sources:
  cavi_score: { value: 4.6, fetched_at: ..., cache_ttl: 86400 }
  versions: { count: 6, fetched_at: ... }
  # ...
```

**关键规则**：数据快照必须保存，用于：
- 调试（"为什么这份报告价格不对？"）
- 回放（同一快照 → 同一 MD 哈希）
- 审计（3 个月后查历史数据）

### 2.6 失败处理

| 失败节点 | 错误码 | 处理 |
|---------|--------|------|
| 接入 | E001/E002 | 修正参数，不重试 |
| 数据 | E101 | 重试 3 次（200ms / 1s / 立即）|
| 数据 | E102 | 阻塞 + 报警（关键数据问题）|
| 数据 | E103 | 提示"数据陈旧"，PM 决定是否重生成 |
| 生成 | E201/E202 | 不重试，需修数据 |
| 生成 | **E203** | **AI 改数字是 P0，报警，重生成** |
| 生成 | E301/E302 | 重试 1 次（30s）|
| 落地 | E401/E500 | 重试 1 次（60s）|

### 2.7 关键指标

| 指标 | 公式 | 目标 |
|------|------|------|
| 生成成功率 | success / total | > 99% |
| 字段完整率 | 必填非空 / 必填总数 | > 99% |
| 跨字段一致率 | 一致 / 总校验 | > 99.5% |
| **AI 字段合规率** | **AI 字段不篡改 / AI 字段总数** | **100%** |
| 西语 eyebrow 命中率 | 字面正确 / 总段数 | 100% |
| 单次生成耗时 | end - start | < 60s |
| P99 延迟 | 99% 调用耗时 | < 60s |
| 缓存命中率 | cache_hits / total_fetches | > 70% |

## 三、功能需求

### 3.1 MD 文档规范

#### 3.1.1 文件命名

**命名规则**：`{model}-{year}.md`

**示例**：
- `reports/es/nissan-versa-2026.md`

> v1.1 更新：去掉了 `{series_id}` 前缀和 `{lang}` 后缀（语言通过目录区分）。详细见 `docs/MD-数据-需求清单.md`。

#### 3.1.2 Frontmatter 必填字段

```yaml
---
title: Nissan Versa 2026 购车指南
series_id: 356              # CAVI 系统车系 ID
model: nissan-versa         # 车型名（小写、连字符）
year: 2026
market: MX                  # 市场：MX=墨西哥
lang: es                    # 语言：es=西班牙语 / zh=中文
energy_type: 燃油           # 燃油 / 混动 / 纯电
body_type: Sedán            # 车身形式
device: pc                  # 渲染设备：pc / h5
generated_at: 2026-08-27
cavi_score: 4.6             # CAVI 综合评分（系统）
cavi_recommend: 89          # 推荐率%（系统）
cavi_verdict: Balance precio/espacio/seguridad inmejorable   # 一句洞察（混合）
---
```

> v1.1 强化：每个字段都明确标"系统 vs AI"来源。详见 `docs/MD-数据-需求清单.md`。

#### 3.1.3 文档章节结构（v3.0）

> 8 段结构 = 首屏（Hero + Spec strip + Trim selector + Compare bar）+ 02..08 七个内容段。
> "概览"和"参数"不再分两段；参数融入首屏 Spec strip，身份/定位作为 Hero 元信息。

| 段 | block-eyebrow（西语） | block-title | 必须包含 |
|----|---------------------|------------|----------|
| 首屏 | (无 eyebrow，Hero 段) | 车名 + Spec strip + Trim selector + Compare bar | 车名、3 核心数据（Spec strip）、版本选择、对比条 |
| 02 | `02 · PRECIO Y FINANCIAMIENTO` | Precio y planes | 主价卡（distribuidor 深色）+ 3 补充卡（BBVA / Nissan financing / 交换补贴）+ cta-bar "¿Calcular tu cuota?" |
| 03 | `03 · CORE SELLING POINTS` | Lo que destaca | 3-4 个核心数据指标（大数字+短标签）+ 1 段洞察（配大图） |
| 04 | `04 · CAVI · RESEÑAS` | Reseñas de usuarios | CAVI 综合评分 + 推荐率 + 4 维度细分（cajuela / consumo / seguridad / ruido）+ 精选评论 2-3 条 |
| 05 | `05 · COST` | Costo anual | 年度总成本 + 5 项并列明细（fuel / insurance / maintenance / depreciation / tax）+ 省钱建议 |
| 06 | `06 · PROTECTION` | Cobertura post-compra | 质保年限+里程、保养包次数+里程、服务网络规模、支持项目 Tag |
| 07 | `07 · COMPETITORS` | ¿Qué comparar? | 3 张并排卡（VW Virtus / Kia K3 / Mazda 2 类直接对标）+ ALTERNATIVA / PREMIUM 标签 |
| 08 | `08 · SIGUIENTE PASO` | ¿Listo para decidir? | 3 张 next-card：WhatsApp 顾问 / 预约试驾 / Cavi AI |

**配套全局元素**（不属于 8 段之一，但所有报告必备）：
- Hero CTA：黄底"Consultar planes"按钮（直链 finance apply）
- Fixed bottom：窄 WhatsApp 图标 + 橙色"Llamar"按钮
- 章节内 cta-bar：每个 block 末尾的可量化小 CTA（"¿Calcular tu cuota? · Compara hasta 3 bancos · 1 min"）

### 3.2 Skill 规范

#### 3.2.1 输入参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `series_id` | int | ✅ | 356 | 车系 ID（当前仅 Versa）|
| `force_update` | bool | ❌ | false | 强制更新（忽略缓存）|
| `priority` | enum | ❌ | normal | 任务优先级：high / normal / low |
| `callback_url` | url | ❌ | - | 异步任务完成回调 URL |
| `metadata` | object | ❌ | - | 调用方附加元数据 |

> v1.1 简化：去掉 `market` / `lang` / `template_id`（当前业务 1 个标杆，固定）。详细见 `docs/MD-生成-SKILL-调用契约.md`。

#### 3.2.2 输出规范

```json
{
  "status": "success",
  "file_path": "/reports/es/nissan-versa-2026.md",
  "model": "nissan-versa",
  "series_id": 356,
  "data_version": "v20260827-1430",
  "generated_at": "2026-08-27T12:00:00Z",
  "duration_ms": 4200,
  "validation": {
    "auto_pass": true,
    "fields_complete": "99.5%",
    "consistency_check": "pass",
    "ai_compliance_check": "pass",
    "warnings": []
  }
}
```

#### 3.2.3 错误处理

| 错误码 | 说明 | 处理方式 |
|---|---|---|
| E001 | 输入参数缺失或非法 | 修正参数，不重试 |
| E002 | series_id 不在白名单 | 暂不支持其他车型 |
| E101 | 数据源获取失败（3 次重试后）| 重试 1 次（60s）|
| E102 | 关键字段缺失（价格/版本/CAVI）| 阻塞，报警，PM 介入 |
| E103 | 数据陈旧（关键字段 2× TTL）| 提示"数据陈旧"，PM 决定 |
| E201 | 自动校验不通过 | 不重试，需修数据 |
| E202 | 跨字段不一致 | 不重试，需修数据 |
| **E203** | **AI 润色时篡改系统数字**（v1.1 新增 P0）| **不重试，重生成，报警** |
| E301 | AI 调用失败 | 重试 1 次（30s）|
| E302 | AI 返回非法格式 | 重试 1 次（30s）|
| E401 | 超时（> 60s）| 重试 1 次（60s）|
| E500 | 系统错误 | 报警 + 重试 |
